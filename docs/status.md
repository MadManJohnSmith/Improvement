- Motivo registrado: la unidad RehabWeb (RETAINED F6-DUPLICATE-CONVERSATION-500, transcritos de ~16 pasos, 56 requests, 0 denials de ruta) murió porque conversaciones mayores de 64 KiB recibían 400 fail-closed del receptor; el tope era la constante fija de 64 KiB. Ahora el tope se impone en las tres capas del lanzamiento (frame del pipe, predicate del broker y Content-Length del receptor) y el launcher comunica el valor en argv del receptor como entero no secreto (`scripts/host_launcher.py`).
- Regresiones nuevas en `tests/test_inference_channel.py`: payload >64 KiB aceptado con el default, denegado con tope rebajado por lanzamiento y sobre el tope duro incluso pidiéndolo, validación fail-closed del argumento, campos de razonamiento y partes textuales de assistant aceptados (incluida la segunda pierna con `tool_calls`), diez formas malformadas de reasoning/partes rechazadas, partes textuales de `user` seguidas denegadas, y camino real por `host_launcher` con payload grande (200) y tope rebajado (400 del receptor sin hit upstream). Suite completa: **31 tests Python aprobados** con runtime instalado.
- Sin sonda real adicional en esta unidad: el formato se comprobó contra la fuente del runtime instalado y los transcritos existentes; el relanzamiento de la unidad RehabWeb ejercitará el canal completo en real. Presupuesto/cuotas fijos host-side, sin proxy general; sin cambios de routing global, credenciales, productos ni presets distribuidos.

## Antecedentes externos, no pruebas de esta distribución

El kit previo contiene publicador/resolver Cordis y ensayos deterministas reportados, fixture de contrato y QA del piloto. Su lector está ligado a tres archivos de un caso, sus bindings y scripts tienen alcance de ensayo; no se distribuye como adaptador universal. Se preservó todo el código en el archivo externo para reutilización dirigida, no se reconstruyó ni se ejecutó. El enlace histórico de dependencias al producto permanece intacto; el archivo no es operativo.

El paquete instalado DSH 0.1.5-rc.1 fue inspeccionado y sus servicios nativos ejecutados con Node 26.8.1. Ver setup-dsh.md para alcance y reproducción.

## Pendiente

El contrato v0.1 queda cerrado como operación acotada, no como autonomía. El framework añade contratos locales para capability externa, partición/consolidación de auditoría, cola CLI y archivo circular compacto; estas funciones validan artefactos, pero no conceden permisos ni sustituyen al Host. El piloto real externo de Syncify quedó `RETAINED`: onboarding e inventario pasaron; Cargo alcanzó el checkout real pero `frontendDist`/proc-macro bloqueó compilación y UI no tenía `node_modules`. Falta cargar el preset neutral mediante Creator/DSH, resolver dependencias con autorización y demostrar subagentes/QA efectivos. Presets dedicados activos, continuación Host, QA automática, límites durables, recuperación y transferencia a segundo proyecto real siguen pendientes hasta evidencia externa. El publicador histórico no se necesita para recibos locales de una unidad. No hubo llamadas de modelos, instalación, cambios globales ni QA independiente en esta reorganización.

Remoto origin configurado; publicación sujeta a autorización y autenticación efectiva. El repositorio es canónico: artefactos de ejecución y datos privados permanecen fuera del árbol. `AGENTS.md` establece las reglas de mantenimiento y evaluación con DSH Standard. Licencia pública pendiente del titular. La preparación para GitHub no equivale a publicación ni a motor completo.
